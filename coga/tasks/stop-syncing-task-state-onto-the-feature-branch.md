## Description

The feature-branch dispatcher shared by `sync_task_state` and the catch-all
`sync_coga_state` sweep lands non-union overlay paths on the control branch **and also
commits the caller's local paths on the current branch**. `src/coga/git.py:9-17` states
the local commit is deliberate — "so the agent's checkout reflects the ticket state it
works against" — but in a single-checkout repo the published copy causes phantom PR
conflicts.

The observed duplicate pair came from `sync_coga_state`, not the narrower lifecycle
helper: both commits are titled `Sync coga state`, and the feature-side commit touches
five unrelated tasks. In `manycore-com/magicator2` on branch
`claude/observation-partial-evidence`:

| commit | contained in | paths |
|---|---|---|
| `d93ab1973` | feature branch only | 5 ticket frontmatters |
| `51b0d18f8` | `main`, `origin/main` | the same 5, byte-identical |
| `cf32b85e2` | feature branch only | 1 ticket |
| `06c6bb057` | `main`, `origin/main` | the same 1, byte-identical |

That repo's `AGENTS.md` mandates ordinary branches in one primary checkout (no linked
worktrees, no `/tmp` clones), so `coga bump` always runs with HEAD on the feature branch
and every ticket pays this. PR #867 there carried `coga/log.md` and
`coga/tasks/observation-loop/next/3-debug-observation-cli.md` into its file list and cost a
base-sync merge that produced no product-source conflict at all; PR #866 is the earlier
precedent.

**Rebase does not clean it up, and the reason is specific.** Against the fetched control
tip, commits touching only `coga/tasks/**` are patch-equivalent and can drop during rebase.
The surviving commits touch `coga/log.md`: `eb348d598`, `aa73f331b`, `543e077f1`, and
`27358fcaf`. `log.md` is an append-only `merge=union` file, so the branches' copies diverge
by preceding content and an audit append is not patch-equivalent at a different offset.

Those survivors cannot be deleted safely. `sync_log` deliberately keeps ordinary
feature-branch audit commits local until the PR merges, and the exact lines added by
`aa73f331b`, `543e077f1`, and `27358fcaf` have a zero count in the observed
`main:coga/log.md`. Dropping them deletes the only durable copy. `open_pr()` also commits
the pending launch line before its clean-tree gate, so a one-time pre-PR cleanup cannot
guarantee a log-free branch.

The generated-state surface is wider than tasks and the audit log. Coga's catch-all sweep
also commits command-owned `merge=union` files such as
`coga/recurring/digest/spool.md`; commit `eb348d598` in the same incident carries that
spool beside task and log state. It also commits mixed-purpose files containing
command-owned cursors: the digest consumer writes `### Digest State` inside
`coga/recurring/digest/ticket.md`, and `c5f5f9274` is a catch-all state commit that changed
that cursor. Publication checks must use the command's captured generated paths and bytes
rather than a permanently hard-coded path list or whole-file classification.

There is no way to opt out of just this half. `_ALLOWED_SHARED_GIT_KEYS` (`config.py:458`)
admits only `enabled`, `remote`, and `control_branch`, and `[git] enabled = false` disables
the control landing too.

## Context

Filed from `manycore-com/magicator2`, ticket
`coga/stop-coga-bump-from-stranding-state-commits-on-a-f`, whose owner settled the policy
question on 2026-08-25: **machine-generated Coga state and audit history are canonical on
the control branch.** A feature checkout may mirror them temporarily while a session runs,
but the mirror is operational state rather than review payload. Coga, not an agent-authored
rebase recipe, owns reconciling it before publication. Hand-authored contexts, skills,
workflows, configuration, and ticket prose remain ordinary feature work even if Coga's
catch-all sweep happened to commit them.

### Required publication boundary

Before any Coga path publishes a feature branch, it must:

1. Capture the exact paths and byte snapshots generated by the lifecycle command. Do not
   classify a blanket `coga/**` pathspec or a commit subject as generated state.
2. Land exact ticket/cursor bytes and union-land the command's owned audit and queue
   appends on the fetched control tip under the existing compare-and-swap safeguards.
3. Reconcile the feature branch onto that accepted control state while preserving product
   commits and hand-authored Coga changes. Keeping the checkout current and clean remains a
   requirement; simply removing the local commit is insufficient.
4. Verify with a path-producing diff against that fetched tip that no machine-generated
   lifecycle, audit, queue, or cursor state remains in the feature payload. The captured
   generated-path and byte manifest must remain authoritative when new state writers are
   added, especially for mixed-purpose ticket files. The implementation's publishability
   classifier must use that byte-level ownership too: a blanket `coga/tasks/**` exclusion
   currently rejects a valid PR whose only implementation is deliberate ticket prose.
5. Fail closed if concurrent material drift makes normalization unsafe. Never delete audit
   evidence or overwrite authored Coga files to make the check pass.

This boundary must run after `open-pr` commits its pending launch audit and writes the
generated `pr:` record, then repeat after later lifecycle publication to an already-open
PR. Otherwise those writes or the following gated bump simply reintroduce the state after
a one-time cleanup. Whether the implementation rebases or uses an equivalent safe
normalization is an implementation decision, but agents must not perform the cleanup by
hand.

## Implemented

`git.py::_reconcile_feature_payload`, run at every ordinary feature-branch sync
after the control landing and before any branch publication, plus the byte-level
publishability classifier in `open_pr.py`. Commit `3f45c8f0`, rebased onto
`origin/main` at `0098e75a`.

**The mechanism was forced, not chosen.** Keeping the checkout current *and*
clean puts the generated bytes in the feature branch's tree, so
`git diff <control-tip>...HEAD` lists them unless the merge base holds the same
bytes — and only the control commit that just accepted them does. So
reconciling means making that exact commit reachable. Two alternatives were
worked through and rejected on the constraint, not on taste: a compensating
revert (`_build_feature_compensation_tree` already exists for the strict-assist
failure path) would leave the checkout rendering the *pre-transition* ticket,
which breaks the next session's read; and a synthetic two-parent commit whose
tree is not a real merge would render the PR as reverting the control branch.

Against the five required properties:

1. *Exact captured manifest.* `_generated_commit_rels` takes the caller's armed
   snapshot when there is one, otherwise the exact delta of the state commit
   this command just made (`before..generated_oid`). Never a `coga/**` pathspec
   or a commit subject, so a new state writer is covered the moment it writes
   and a mixed-purpose file (the digest ticket's `### Digest State` cursor
   beside authored prose) is owned only to the extent this command changed it.
2. *Land first, under existing safeguards.* The ordinary feature path now
   union-lands the command's own `merge=union` files onto the fetched control
   tip (`_dispatch_branch_sync`), and `sync_log`'s plain feature path does the
   same. This is the load-bearing ordering: an append leaves the review payload
   only because control durably holds it, so no audit line can be dropped.
3. *Reconcile preserving everything else.* A branch that carried nothing but
   this command's generated state adopts the control commit (`reset --soft`
   over identical trees) and ends with no lifecycle commit at all; a branch with
   real work merges it, keeping product commits and hand-authored Coga changes.
4. *Path-producing verification.* `git diff --name-only <accepted>...HEAD`
   restricted to the manifest. Nothing is inferred from the merge exiting zero.
5. *Fail closed, never raise.* The control landing already succeeded, so a
   conflict or drift reports on stderr and leaves the branch exactly as it was.
   No audit evidence deleted, no authored file overwritten.

`_land_paths_on_control_branch` now returns the accepted control OID, which the
boundary needs; `publish_current_branch` pushes the post-reconcile HEAD.

## Findings

- **The adopt path also removed a real nondeterminism.** Two `commit-tree` calls
  with the same tree, parent, message and second produce the *same commit
  object*. Once union files ride the control land, the feature commit and the
  control commit have identical trees, so on the first sync after branching they
  frequently collide — and whether they did decided the shape of history.
  `reset --soft` to the accepted commit makes both outcomes identical.
- **Two existing tests encoded the policy this ticket reverses** and were
  rewritten, not patched around: `sync_log`'s "committed locally only" and
  `sync_coga_state`'s "keeps union local on feature". Both now assert the
  append is durable on control *and* absent from the payload.
- **`test_open_pr_rejects_divergent_ticket_overlap_in_single_checkout` stopped
  firing**, and that is the fix working. Its divergence came from the branch
  stranding a ticket copy; there is no longer one. It was rewritten to create
  divergence the way it can still legitimately arise — deliberate ticket prose
  committed on the branch while another process edits the same ticket on
  control — so the gate keeps guarding a real conflict.

## Notes for review

The behavior change users will notice: an ordinary feature-branch lifecycle
sync now base-syncs the branch onto the control tip. That is consistent with
existing policy — `code/implement` already requires freshening before handoff
and `coga open-pr` already refuses a branch missing material commits from
`origin/main`. Two honest qualifications, both from self-QA: at `open-pr` time
the merge's only delta is bytes the branch already has, but at an arbitrary
`bump`/`mark`/`block` it is whatever landed on control since the fork, which is
why that integration now reports itself; and when it conflicts, the boundary
declines, says so, and leaves the branch untouched.
