### Reported problem

The Dream ticket body mentions its own report headings, including `## Dream Skill: validate-drift` and `## Dream Skill: <name>`. An agent removing duplicated recipe output by searching the whole ticket for the heading text can mistake those inline examples for actual blackboard sections. The reported W37 run deleted a real report this way. W43 repeated the failure after an accidental double run of `coga run validate-drift`; both real report sections were lost and had to be regenerated by running the idempotent recipe again.

This is an agent-editing hazard reported by the client, not evidence that Coga's existing Markdown parser has that bug. Current source still includes the body examples, so scope the correction to the actual unsafe editing instruction or operation.

### Requested outcome

Document and use one safe rule for locating report sections: first isolate the region below the ticket's own-line blackboard fence, then match actual level-two headings at line start, respecting fenced Markdown examples. Inline heading text in the ticket body must never count as a section.

Keep the canonical guidance in `docs/contexts/coga/blackboard/SKILL.md` and its packaged counterpart consistent, and have the Dream template point to the owning rule. Check existing section helpers before introducing another parser. Verify the worked case with body mentions, actual duplicate report sections, fenced examples, and unrelated blackboard notes: the intended report and unrelated content must survive.

Evaluate whether a repeated invocation should replace its own report or append history, but do not silently change every recipe's history semantics as part of documenting safe section matching. If code behavior changes, add focused regression coverage.
